NN-BASED HOMOGRAPHY QUALITY ESTIMATION — PLAN
==============================================

Goal: a lightweight PyTorch model that takes a pair of binary masks
(mask_A_warped, mask_B) and outputs:
  - predicted_rmse (px): estimated corner transfer error, reliable up to
    N_clip (~30px); values above N_clip mean "bad", exact magnitude unused.
  - sigma (px): learned aleatoric uncertainty in the same pixel units.

Inputs:
  mask_A_warped = reference mask warped by the candidate homography H
  mask_B        = current-frame segmentation mask (from SAM)

Output is always in absolute pixel units. "I think the alignment error is
~5px ± 2px."

Two architectures are proposed. Option E (transformer on boundary point
sets) is primary; Option C (2D CNN on SDF crops) is the backup / ablation
baseline. The preprocessing pipeline is shared between them.

Evaluation (unchanged from existing pipeline):
  Tier 1 — gross regime: TPR/TNR at 15px GT error threshold.
            Predict "good" if predicted_rmse < 15px.
  Tier 2 — fine regime: Spearman r(−predicted_rmse, −GT_error) on frames
            with GT error < 15px only.


======================================================================
SECTION 1 — SHARED PREPROCESSING PIPELINE
======================================================================

Both architectures consume the same intermediate representations, computed
once per (ref, mask_B, H) triple, where ref = ReferenceContour (precomputed
once at initialisation from the clean first-frame mask).

Phase 0 (once at init, reuses existing ReferenceContour):
        Extract and resample reference contour from clean first-frame mask
        → N=128 points {p_i} at uniform arc-length spacing.
        Compute tangent directions (sin θ_i, cos θ_i) from the ordered
        contour. Store alongside the existing curvature and weights.

        Resampling note: for tiny objects (perimeter < 256px) upsampling
        produces near-duplicate points — redundant but harmless for
        attention. For large objects (perimeter >> 256px) one sample covers
        ~perimeter/128 px — adequate for estimating 5–30px errors.

Per-frame steps:

Step 1: Warp reference contour points directly.
        p'_i = H · p_i  (homogeneous warp, existing _warp_points).
        Mark each p'_i: is_in_view[i] = 1 if within [0,W)×[0,H), else 0.
        Do NOT extract contour from a rasterised warped mask — warping
        the clean reference points preserves smooth contour geometry and
        avoids jagged rasterisation artefacts.

Step 2: Compute SDF_B.
        SDF_B = _compute_sdf(mask_B)   # existing, original pixel units

Step 3: Warp mask_A to get mask_A' for SDF_A' (needed for ∂B side only).
        mask_A' = cv2.warpPerspective(mask_A, H)
        SDF_A'  = _compute_sdf(mask_A')
        Using the directly warped binary mask (not cv2.fillPoly on the
        resampled contour) preserves sharp corners, fine detail, and
        multi-part mask topology. The resulting raster is slightly jagged,
        but the distance transform smooths this: rasterisation error is
        ~1px, negligible for the 5–30px regime we care about.
        Requires storing mask_A in ReferenceContour (one binary image,
        kept in memory for the lifetime of the target).

Step 4: Extract and resample ∂B.
        ∂B = resample(mask_B, N=128)   # uniform arc-length spacing
        Compute tangent directions (sin φ_j, cos φ_j) for each ∂B point.
        All ∂B points are in-frame; is_in_view = 1 for all.

Step 5: Compute bounding box for position encoding.
        bbox = union of:
          - in-view ∂A' points only  (OOF points excluded — they are
            outside the image and would incorrectly stretch the bbox)
          - all ∂B points
        Expand by 10% on each side. Clip to image boundaries.
        Normalised coordinates: x̂ = (x − x_min)/(x_max − x_min), same y.

Step 6: Sample SDFs at boundary points.
        For in-view ∂A' points:  sdf_B_at_A'[i] = bilinear(SDF_B, p'_i)
        For OOF    ∂A' points:  sdf_B_at_A'[i] = +D_large   (e.g. image
                                diagonal — definitely outside B)
        For ∂B points:          sdf_A'_at_B[j] = bilinear(SDF_A', q_j)

Step 7 (Option C only): crop and rescale SDF maps (see Section 2b).

Steps 1–6 are shared. The branch point is Step 7.


======================================================================
SECTION 2a — PRIMARY ARCHITECTURE: BOUNDARY TRANSFORMER (OPTION E)
======================================================================

Inspired by SuperGlue-style bipartite set matching. The two boundary
point sets are processed jointly with self- and cross-attention.

----------------------------------------------------------------------
2a.1 Per-point feature vectors
----------------------------------------------------------------------

For each ∂A' point p'_i (warped reference):
  raw_features = [sdf_B_at_A'[i],  sin θ_i,  cos θ_i,  is_in_view[i]]
  (4 values; sdf_B imputed as +D_large for OOF points)

For each ∂B point q_j (SAM mask):
  raw_features = [sdf_A'_at_B[j],  sin φ_j,  cos φ_j,  1.0]
  (4 values; is_in_view always 1 for ∂B)

SDF values are in original pixel units (signed: positive outside the other
mask, negative inside). The is_in_view flag signals OOF to the network so
it can learn to treat these points as "explained absence" rather than
evidence of bad H.

Position encoding γ(x̂, ŷ):
  Computed from bbox defined in Step 5 (in-view ∂A' + ∂B points only).
    x̂ = (x − x_min)/(x_max − x_min),  ŷ = (y − y_min)/(y_max − y_min)
  For OOF points: coordinates are still computed (values fall outside
  [0,1]²) and passed through γ — sin/cos are defined everywhere.
  The is_in_view=0 flag is the primary OOF signal; the position encoding
  for OOF points provides approximate spatial context (where the point
  would appear relative to the visible region).

  Fourier features with K=4:
    γ = [sin(2^k π x̂), cos(2^k π x̂), sin(2^k π ŷ), cos(2^k π ŷ)]_{k=0..3}
  → 16 values per point.

Full input per point: [raw_features (4) | γ (16)] = 20 values.

Set-type embedding: a learned table of shape (2, d_model) — one row for
∂A', one for ∂B — added to each projected token. Tells the network which
mask each point belongs to (conceptually a binary A/B flag, represented
as a learnable d_model-dimensional vector).

----------------------------------------------------------------------
2a.2 Token embedding
----------------------------------------------------------------------

Shared pointwise MLP applied independently to each point (regardless of
which set it belongs to):

  Linear(19 → d_model) + LayerNorm

Then add the set-type embedding:
  token_A[i] = embed(raw_A[i]) + type_embed[0]
  token_B[j] = embed(raw_B[j]) + type_embed[1]

----------------------------------------------------------------------
2a.3 Transformer blocks
----------------------------------------------------------------------

Repeated L=2 times:

  1. Self-attention within ∂A'   (N×N attention)
  2. Self-attention within ∂B    (N×N attention)
  3. Cross-attention ∂A' → ∂B   (each ∂A' token queries all ∂B tokens)
  4. Cross-attention ∂B → ∂A'   (each ∂B token queries all ∂A' tokens)

Each attention block: standard multi-head attention + residual + LayerNorm.
No positional encoding injected into Q/K/V — the position information is
already in the token features via γ(x, y).

Self-attention captures global boundary context ("where am I on this
shape?"). Cross-attention discovers correspondences and mismatches between
the two boundaries ("which part of B aligns with this part of A'?").

----------------------------------------------------------------------
2a.4 Aggregation and output heads
----------------------------------------------------------------------

After L blocks:
  v_A = mean_pool(token_A)      →  d_model vector
  v_B = mean_pool(token_B)      →  d_model vector
  v   = concat([v_A, v_B])      →  2·d_model vector

Two output heads (each: Linear(2·d_model → 64) + ReLU + Linear(64 → 1)):

  RMSE head:  softplus(raw) → predicted_rmse  (px, non-negative)
  Sigma head: raw           → log_sigma        (clipped to [−5, 5])
              sigma = exp(log_sigma)           (px)

----------------------------------------------------------------------
2a.5 Model size
----------------------------------------------------------------------

  d_model = 64,  heads = 4,  L = 2,  N = 128
  Input features per point: 20 (4 raw + 16 Fourier PE)
  Input projection + type embeds:  ~3K params
  Transformer blocks (L=2):        ~100K params
  Output heads:                    ~10K params
  Total:                           ~115K params

Single forward pass: ~2ms GPU (N=128, batch=1).


======================================================================
SECTION 2b — BACKUP ARCHITECTURE: SDF-CROP CNN (OPTION C)
======================================================================

Retained as baseline and for ablation. Shares Steps 1–5 of preprocessing.

----------------------------------------------------------------------
2b.1 Input representation
----------------------------------------------------------------------

Four-channel 128×128 image:
  Ch 0 — binary_A'  (0.0/1.0)
  Ch 1 — SDF_A'     (rescaled)
  Ch 2 — binary_B   (0.0/1.0)
  Ch 3 — SDF_B      (rescaled)

Spatial normalisation (isotropic — single scale factor for both axes):
  1. Crop to bounding box of union(A', B), expanded 20%, clipped to frame.
  2. s = output_size / max(crop_h, crop_w).     ← single isotropic scale
  3. Resize to 128×128 (bilinear for SDFs, nearest for binary).
     Pad the shorter dimension to maintain aspect ratio.
  4. Rescale SDF values:  SDF_resized = SDF_original × s.
     SDF values are now in resized-crop-pixel units.

After rescaling, SDF magnitudes and spatial patterns are consistent:
the same absolute alignment error produces the same SDF value in the
same spatial location regardless of object size.

----------------------------------------------------------------------
2b.2 Architecture
----------------------------------------------------------------------

Depthwise-separable CNN:
  Block 1: stride-2 DWSConv(4→32)    → 32 × 64 × 64
  Block 2: stride-2 DWSConv(32→64)   → 64 × 32 × 32
  Block 3: stride-2 DWSConv(64→128)  → 128 × 16 × 16
  Block 4: stride-2 DWSConv(128→128) → 128 × 8 × 8
  Global average pooling             → 128-dim vector

Output heads: same structure as Option E.
Output rescaling: multiply predicted_rmse and sigma by (1/s) before loss
and at inference to convert back to absolute pixel units.

Total parameters: ~150K.

----------------------------------------------------------------------
2b.3 Known limitation
----------------------------------------------------------------------

For highly elongated objects (e.g., 50×500px) the isotropic crop means the
thin dimension occupies only ~13/128 of the canvas; effective CNN resolution
in that direction is low. This is a consequence of the geometry rather than
a flaw in the approach.


======================================================================
SECTION 3 — GROUND TRUTH
======================================================================

GT error = corner RMSE:
  The four corners of the bounding box of mask_A (reference frame) are
  warped by H_true and by H_candidate. RMSE is computed in image px.
  (Same as alignment_error() in flatsam2/metrics.py.)

Censored regression target:
  - Uncensored samples (RMSE ≤ N_clip): GT = RMSE, full loss.
  - Censored samples   (RMSE > N_clip): one-sided loss only (see Sec. 5).

N_clip = 30px default. The network is free to output any value ≥ 0; values
above N_clip for bad samples are uninformative and receive no gradient.


======================================================================
SECTION 4 — LOSS FUNCTION
======================================================================

Censored heteroscedastic regression. Let pred = predicted_rmse, ls = log_sigma.

For uncensored samples (RMSE_i ≤ N_clip):
  L_i = (pred_i − RMSE_i)² · exp(−2·ls_i) + 2·ls_i

For censored samples (RMSE_i > N_clip):
  L_i = relu(N_clip − pred_i)²
  (One-sided squared hinge: zero when pred ≥ N_clip. No uncertainty term —
  sigma is uninformative for clearly-wrong hypotheses.)

Full batch loss: L = mean_i(L_i).

Initialise log_sigma bias to 0 (sigma_init = 1px) so training starts near
plain MSE.

For Option C: pred and RMSE are both in absolute px (pred is rescaled by 1/s
before the loss, so the loss is always in absolute px — N_clip is always 30px,
no per-sample adjustment needed).


======================================================================
SECTION 5 — SYNTHETIC DATA GENERATION
======================================================================

All data generated synthetically on-the-fly during training. No real
labelled data required. Both architectures train on the same generated
samples (only the preprocessing branch differs from Step 6 onward).

----------------------------------------------------------------------
5.1 Shape library
----------------------------------------------------------------------

  A — Convex polygons   (40%): N=5..20 vertices, aspect ratio 0.3..3.0,
      scale 10%..60% of canvas area.
  B — Non-convex shapes (40%): stars, L/T/C shapes, concave polygons.
  C — Smooth shapes     (20%): ellipses, rounded rectangles, Bezier curves.

Canvas: 720×1280 px. Objects placed at random positions and scales.

----------------------------------------------------------------------
5.2 Scene generation (one sample)
----------------------------------------------------------------------

Step 1: Sample shape → mask_A. Record 4 bounding-box corners.

Step 2: Sample scene transform T (realistic homography):
        rotation ±30°, scale 0.6..1.6, translation ±15%, mild projective.

Step 3: mask_B_clean = warp(mask_A, T), clipped to canvas.

Step 4: Apply mask_B augmentation (one mode per sample):
        clean    (15%): mask_B = mask_B_clean
        occlude  (35%): remove random occluder, 5%..90% of area
        spill    (20%): add random blob tangent to boundary, 5%..40% area
        noisy    (15%): morphological noise (dilate+erode, kernel 1..7px)
        combo    (15%): two of the above

Step 5: Sample error regime and construct H_candidate:
        perfect    (10%): H_candidate = T, RMSE = 0
        good       (35%): target RMSE ~ LogUniform(0.5, 15) px
        borderline (20%): target RMSE ~ Uniform(15, 30) px
        bad        (35%): large random perturbation, RMSE >> N_clip

        For good/borderline: binary-search perturbation magnitude to hit
        target RMSE on the 4 reference corners.
        For bad: sample large random perturbation (no precise targeting).

Step 6: Compute inputs via shared pipeline (Section 1).

Step 7: Compute clamping flag and GT:
        RMSE_actual = corner_rmse(T, H_candidate, corners_of_mask_A)
        censored    = (RMSE_actual > N_clip)
        gt          = RMSE_actual   (used in loss directly, not clamped)

Output: (preprocessed inputs, gt, censored_flag)

----------------------------------------------------------------------
5.3 Dataset size
----------------------------------------------------------------------

500K training / 50K validation samples (fixed seeds for val).
Generated on-the-fly; no disk serialisation needed.


======================================================================
SECTION 6 — TRAINING
======================================================================

Applies to both architectures identically (same GT, same loss, same
augmentation — only the model differs).

Optimiser:  AdamW, lr=3e-4, weight_decay=1e-4
Schedule:   CosineAnnealingLR, 50 epochs (1 epoch = 10K gradient steps)
Batch size: 128
Grad clip:  max_norm=1.0
Early stop: validation loss, patience=5 epochs

Augmentation on the generated sample (applied before preprocessing):
  - Random horizontal flip of both masks (p=0.5)
  - Random vertical flip of both masks   (p=0.5)
  (For Option E: flip coordinates accordingly. For Option C: flip the crops.)


======================================================================
SECTION 7 — INFERENCE
======================================================================

Shared preprocessing (Steps 1–5 of Section 1), then:

Option E:
  Forward pass on (token_A, token_B) → (raw_rmse, log_sigma)
  predicted_rmse = softplus(raw_rmse)     # absolute px, unbounded
  sigma          = exp(clamp(log_sigma, −5, 5))

Option C:
  Forward pass on 4×128×128 crop → (raw_rmse, log_sigma)
  predicted_rmse = softplus(raw_rmse) / s  # rescale to absolute px
  sigma          = exp(clamp(log_sigma, −5, 5)) / s

Return: (predicted_rmse, sigma) in absolute pixel units for both.

Interpretation:
  predicted_rmse < 15px        → good homography  (Tier 1 threshold)
  15 ≤ predicted_rmse < N_clip → borderline / imprecise
  predicted_rmse ≥ N_clip      → bad; exact value unreliable

Hypothesis comparison: rank candidates by predicted_rmse ascending.
Use sigma to flag low-evidence comparisons (heavy occlusion etc.).


======================================================================
SECTION 8 — EVALUATION
======================================================================

Primary metric (Tier 1):
  TPR = fraction of GT-good frames (GT_error < 15px) where pred_rmse < 15
  TNR = fraction of GT-bad  frames where pred_rmse ≥ 15
  balanced_accuracy = (TPR + TNR) / 2

Fine ranking (Tier 2):
  Spearman r(−predicted_rmse, −GT_error) on GT-good frames only.

Diagnostic: scatter plot of predicted_rmse vs GT corner RMSE on the
validation set, with the identity line and N_clip=30px line overlaid.

Baselines:
  1. Handcrafted assess_homography() confidence score (existing)
  2. Option C CNN (if primary architecture is Option E, and vice versa)


======================================================================
SECTION 9 — SCENARIO SANITY CHECK
======================================================================

E1 (perfect, RMSE=0):
  ∂A' SDF_B values ≈ 0, ∂B SDF_A' values ≈ 0. Cross-attention finds
  tight correspondences. → pred_rmse ≈ 0, sigma small. ✓

E2 (no overlap, RMSE >> 30px):
  ∂A' SDF_B values large positive; ∂B SDF_A' values large positive.
  No cross-attention matches found. → pred_rmse ≥ N_clip. ✓

E3 (segmenter spill, RMSE=0):
  ∂A' SDF_B values ≈ 0 (core boundary aligns). Extra ∂B points (the
  spill) see large SDF_A' (outside A'). Cross-attention: ∂A' finds good
  matches in ∂B core; spill ∂B points find no match in ∂A'. With correct
  H, network trained on many such samples learns: core match is positive
  evidence; unmatched ∂B excess is not evidence of bad H.
  → pred_rmse ≈ 0. ✓

E4 (occlusion, RMSE=0):
  Visible ∂A' points: SDF_B ≈ 0, matched. Occluded ∂A' points: large
  positive SDF_B (outside B), unmatched. Self-attention within ∂A' can
  identify the contiguous occluded segment. Cross-attention: matched
  points have good correspondences; unmatched do not.
  → pred_rmse ≈ 0. For 5% visible: sigma large (little evidence). ✓

E5 (imprecise, RMSE ≈ 10px):
  SDF values have consistent small positive offset. Cross-attention finds
  approximate correspondences. → pred_rmse ≈ 8..12. ✓

E6 (out of frame):
  OOF ∂A' points: is_in_view=0, sdf_B imputed as +D_large. In-view ∂A'
  points behave normally. The network sees a mix of is_in_view=1 (normal
  alignment signal) and is_in_view=0 (explained absence) tokens — it can
  learn not to penalise H for the OOF portion. Bounding box computed from
  in-view points only so the crop stays within the image. ✓

E7 (hypothesis comparison X/Y/Z):
  X (RMSE≈1px): pred ≈ 1px, sigma small.
  Y (RMSE≈10px): pred ≈ 10px, sigma small.
  Z (RMSE≈100px): pred ≥ 30px (clamped regime), sigma moderate.
  Ranking X < Y < Z correct. Fine X vs Y separation is the key case. ✓
